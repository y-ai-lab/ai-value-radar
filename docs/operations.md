# 運用メモ

## 毎日

Telegramの通知を見るだけです。候補に付いた「記事下書き」リンクを開くと、GitHub上のMarkdown下書きを確認できます。末尾の「詳細レポート」からは、監視件数・7日間集計・エラーもスマホで確認できます。通知がない場合でも、Actionsの実行結果は`data/latest.md`、`data/last_report.json`、`data/run_history.json`に残ります。

## 記事下書きの使い方

1. Telegramで候補の「記事下書き」リンクを開く。
2. 下書き内の公式URLを開き、価格・仕様・期限・日本利用・商用利用・Affiliate条件を確認する。
3. 実際にツールを試し、下書きの「筆者の実体験メモ」を埋める。
4. 事実と推測を分け、必要なPR / アフィリエイト表記を記事冒頭に置く。
5. 確認が終わった本文だけをnote等へ手動で公開する。

候補がない回は異常ではありません。重複を除いた結果、今見る価値がある新規・重要更新がなかったという意味です。

自動公開は行いません。下書きは「実際に使ったツールのみ紹介」「誇大表現禁止」を守るための公開前素材です。

## 失敗時

- 一部ソース失敗：`data/errors.jsonl`を確認。残りのソースは続行。
- AI失敗：`last_report.json`の`ai.errors`を確認。ルールベースで継続。
- Telegram失敗：レポートと履歴は保存済み。SecretsまたはBotの受信先を確認。
- Actions失敗：ActionsのRun → job logを確認。手動の`scan`で再実行。

## 7日間の検証

`data/metrics_7d.json`で以下を確認します。

- 朝起きたときに見る価値があった通知数
- 有望判定数とAffiliate可能案件数
- 発信候補数（40点以上）と有望判定数（70点以上）
- 自動生成された記事下書き数と下書き生成エラー数
- 重複率・エラー率・1回の実行時間
- AI呼び出し件数と誤判定数

「通知が来たか」より、「実際にリンク先を確認する価値があったか」を最重要KPIにします。
