# 運用メモ

## 毎日

Telegramの通知を見るだけです。候補に付いた「発信用パック」リンクを開くと、GitHub上のMarkdownパックを確認できます。末尾の「詳細レポート」からは、監視件数・7日間集計・エラーもスマホで確認できます。通知がない場合でも、Actionsの実行結果は`data/latest.md`、`data/last_report.json`、`data/run_history.json`に残ります。

収益候補がない回でも、別枠の「発信ネタ」があれば発信用パックと`data/content_queue.md`が更新されます。収益判定と発信判定は分離しているため、発信を増やす目的で収益条件を緩める必要はありません。

ブラウザで <https://y-ai-lab.github.io/ai-value-radar/> を開くと、Telegramと同じ公開データをカード形式で確認できます。「今回」「発信ネタ」「発信キュー」「7日間」のタブを使い分けます。表示は公開JSONから作られるため、UIにSecretや個人情報は渡りません。

## 発信用パックの使い方

1. Telegramで候補の「発信用パック」リンクを開く。
2. パック内の公式URLを開き、価格・仕様・期限・日本利用・商用利用・Affiliate条件を確認する。
3. 実際にツールを試し、「筆者の実体験メモ」を埋める。
4. note本文・X投稿案・Threads投稿案を、確認できた事実に合わせて修正する。
5. 事実と推測を分け、必要なPR / アフィリエイト表記を記事・投稿の冒頭に置く。
6. 確認が終わった本文・投稿だけをnote等へ手動で公開する。

候補がない回は異常ではありません。重複を除いた結果、今見る価値がある新規・重要更新がなかったという意味です。

自動公開は行いません。下書きは「実際に使ったツールのみ紹介」「誇大表現禁止」を守るための公開前素材です。

## Telegramからの進捗更新

通知に表示された8文字コードを使い、同じTelegramチャットから次のコマンドを送ります。

```text
/good CODE       見る価値があった
/skip CODE       今回は不要だった
/trial CODE      試用中
/used CODE       使用済み
/published CODE 公開済み
/posted CODE x   Xへ投稿済み（note / threads / videoも可）
/queue           キュー全体の進捗
/help            コマンド一覧
```

コマンドは次回の定期実行または手動スキャン時に処理されます。成功するとTelegramへ確認を返し、7日間KPIへ反映します。別チャットからのコマンドは無視します。

## 失敗時

- 一部ソース失敗：`data/errors.jsonl`を確認。残りのソースは続行。
- AI失敗：`last_report.json`の`ai.errors`を確認。ルールベースで継続。
- Telegram失敗：レポートと履歴は保存済み。SecretsまたはBotの受信先を確認。
- Actions失敗：ActionsのRun → job logを確認。手動の`scan`で再実行。
- Telegramコマンド不反映：コードの大文字小文字、対象チャット、次回スキャンの完了を確認。

## 7日間の検証

`data/metrics_7d.json`で以下を確認します。

- 朝起きたときに見る価値があった通知数
- 有望判定数とAffiliate可能案件数
- 発信ネタ数・6切り口/動画パック数・キュー消化数
- `/good`・`/skip`の件数と、実利用ステータス更新数
- 自動生成された発信用パック数とパック生成エラー数
- 重複率・エラー率・1回の実行時間
- AI呼び出し件数と誤判定数

「通知が来たか」より、「実際にリンク先を確認する価値があったか」を最重要KPIにします。
